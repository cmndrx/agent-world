# Interest care implementation evidence — October 15, 2026

This is a partial implementation of the approved pass. Tyler's 68-row matrix remains the requirement review and historical baseline. Current source supports **15 care actions, 53 unavailable interests**. No real residents were reassigned in this pass.

Supported interest IDs: `favorite_meals`, `sweets`, `takeout`, `snacks`, `television`, `board_games`, `naps`, `sleeping_in`, `bubble_baths`, `lazy_days`, `reading`, `personal_goals`, `awards`, `celebrations`, `praise`. Each still needs its matching interest, a reachable available station on the resident's assigned floor, and applicable actual household resources. Safe goal/award/celebration labels describe simulated shared scenes, never real achievements. Meal and takeout are simulated servings; no real ordering or payment occurs.

All actions now require ten active scene seconds for up to +5 happiness, capped at 100, followed by the existing 30-second cooldown. This explicitly replaces immediate general praise/snack rewards. Receipts, revision checks and bounded history remain. The server creates the station plan from saved home/style and authored geometry; client eligibility flags, elapsed timers and client reward amounts are ignored. Sequential renderer heartbeats must identify the pending action, floor and planned approach. Duplicates cannot advance progress. Missing heartbeats after activity starts, work, cancellation, restart, changed layout/resources or unavailable stations cancel without reward. An unstarted scene times out after 60 seconds. No offline catch-up or passive reward exists. The renderer remains the source of visible scene acknowledgments; this is not tamper-proof proof that pixels were displayed by a hostile local client.

Passive home activity selection now follows assigned interests and uses the same reviewed resource predicates/planner as care. No temporary TV, bathtub, cat, bunny or aquarium substitutes remain. Bed-based rest requires a real bed; reading requires an authored bookshelf or placed low shelf; snacks require a placed snack fridge. Lazy-day seating uses authored couches/loveseats/armchairs. Portable meal/candy/takeout/board/journal/trophy/cake props are explicitly permitted scene props, not durable ownership.

Unavailable: all 49 interests without home venue choreography, plus cat companionship, bunny companionship, aquatic pets and painting. Matching saved pet ownership is checked first, but safe pet approach/return and binding to the existing populated aquarium remain unimplemented. These actions stay unavailable even with the right pet/aquarium. Painting needs a persistent easel, which is not placeable. Dog walks still require supported park travel. No placeholder receives happiness.

The authored Family House ground-floor bath currently lacks a safe supported approach under the navigation grid and is unavailable. Its upstairs bath is reachable for upstairs residents and reserved exclusively, as tested; downstairs residents cannot borrow it. No floor-plan editing or resident teleport was used to make care appear available.

Build mode adds free `television` and `fireplace_tv` catalog items; no purchase is needed. The mounted variant snaps to an authored ground-floor fireplace, persists its anchor and rotation, renders a 1.12 × .63m screen above its mantel and follows support-wall/floor visibility. Missing anchors remain owned but unplaced. Server validation rejects forged/duplicate mounts and invalid standalone TV overlap, bounds and navigation. This pass placed nothing in real homes. Upper-floor player TV placement is not implemented; authored upper-floor TVs may qualify for residents on that floor.

`GET /api/care-options` reports server resource/station reasons. `POST /api/care` still requires an active, built home and actual resident membership. `POST /api/care-preferences` permits only validated preference edits to existing saved identities, including inactive homes, without activating/recruiting them. Existing care preserves happiness/cooldowns/history and adds a zero-delta edit entry. Uninitialized identities preserve their existing happiness and absent care/history, using separate preference revisions/receipts. No queue API is involved.
